2 ЗАВДАННЯ

   Метою практичної роботи є дослідження архітектури складної програмної системи та аналіз застосованих архітектурних підходів.


 
3 ОПИС ВИКОНАНОЇ РОБОТИ


3.1 Загальні відомості систему
Назва системи: Discord
Розробник: Discord Inc. 
Призначення системи:
Discord — це популярна комунікаційна платформа, призначена для голосового, текстового та відеозв’язку.
Основні функції:
* Текстові та голосові канали
* Відеодзвінки та трансляції екрану
* Створення та управління серверами
* Система ролей та прав учасників
* Повідомлення, згадки та сповіщення
* Інтеграція з іншими сервісами


3.2 Архітектурний стиль системи
Мікросервісна архітектура з елементами подієво-орієнтованої архітектури (Event-Driven Architecture).
Обґрунтування вибору архітектури:
Discord — це високо масштабована система реального часу, яка одночасно обслуговує десятки мільйонів користувачів.
Мікросервісна архітектура дозволяє:
* Розділити систему на незалежні сервіси (чат, голос, відео, сповіщення, авторизація тощо);
* Масштабувати окремі компоненти незалежно;
* Забезпечити швидку розробку та оновлення різних частин системи.
Подієво-орієнтований підхід (через WebSocket, Phoenix Channels та внутрішні event-брокери) забезпечує:
* Низьку затримку доставки повідомлень;
* Реактивність системи;
* Легке додавання нових функцій без впливу на основний код.
Така комбінація архітектурних стилів є оптимальною для сучасної комунікаційної платформи, яка вимагає високої продуктивності, масштабованості та надійності.
3.3 Основні компоненти системи
Опис підсистем Discord:
* Інтерфейс користувача (Client): Кросплатформний клієнт (десктоп, веб, мобільні додатки), який забезпечує зручний інтерфейс для спілкування, включає чати, голосові канали, відеодзвінки, управління серверами та налаштуваннями.
* Серверна частина (Backend): Масштабована розподілена система серверів, побудована на мікросервісній архітектурі. Відповідає за обробку всіх запитів користувачів у реальному часі.
* Рівень бізнес-логіки: Містить основну логіку системи: управління користувачами, серверами, каналами, ролями, правами доступу, модерацією та інтеграціями.
* Рівень зберігання даних: Комбінація баз даних:
   * PostgreSQL / Cassandra — для основних даних;
   * Redis — для кешування та реального часу;
   * Elasticsearch — для швидкого пошуку повідомлень.
* Допоміжні сервіси: Включають сервіси сповіщень, медіа-серверы (для голосу та відео), CDN для швидкої доставки контенту, сервіси авторизації, аналітики та захисту від DDoS-атак.

3.4 Взаємодія компонентів  
Взаємодія компонентів у Discord побудована за принципом реального часу і базується на поєднанні мікросервісної та подієво-орієнтованої архітектури.


  

Рис 3.1 - UML діаграма компонентів
Діаграма на рисунку 3.1 показує високорівневу архітектуру системи Discord. Вона відображає основні компоненти системи та взаємодію між ними. Основні елементи:
   * Клієнт підключається через API Gateway
   * Основні мікросервіси: Chat Service, Voice Service, Presence, Auth
   * Використання брокера повідомлень Kafka, кешу Redis, баз даних та CD
  

Рис. 3.2 - UML діаграма класів
Діаграма відображає об’єктно-орієнтовану структуру основних сутностей системи Discord. Показує:
   * Класи: User, Member, Server, Channel, VoiceChannel, Message, Notification
   * Відносини між класами (успадкування — extends)
   * Атрибути та основні методи класів
Основні потоки даних:
   * Клієнт (додаток) підключається до серверів через WebSocket для постійного двостороннього зв’язку.
   * При відправці повідомлення дані проходять шлях: Client → Gateway API → Business Logic Services → Message Service → Database + Cache (Redis).
   * Сповіщення про нові повідомлення, оновлення статусів та голосові події миттєво розсилаються всім підписаним клієнтам через WebSocket.
Протоколи взаємодії:
   * WebSocket — основний протокол для реального часу (чат, голос, онлайн-статуси).
   * HTTP/REST — використовується для авторизації, завантаження файлів, створення серверів.
   * WebRTC — для голосових та відеодзвінків (peer-to-peer з медіа-серверами).
   * gRPC — для внутрішньої взаємодії між мікросервісами.
Механізми синхронізації:
   * Event-Driven Architecture — події (наприклад, message_created, user_joined) публікуються через message broker.
   * Redis Pub/Sub та внутрішні event buses для швидкої синхронізації між сервісами.
   * Optimistic UI Updates на клієнті з подальшою синхронізацією з сервером.


3.5 Масштабованість та надійність
Основні механізми забезпечення масштабованості та надійності:
   * Балансування навантаження: Використовуються потужні балансувальники навантаження (Load Balancers) на рівні Gateway та між мікросервісами для рівномірного розподілу трафіку.
   * Відмовостійкість: Застосовується принцип multi-region та multi-AZ розгортання. Використовується реплікація даних і автоматичне перемикання на резервні сервіси (failover).
   * Кешування: Активно використовується Redis для кешування часто запитуваних даних (статуси користувачів, канали, ролі), що значно зменшує навантаження на бази даних.
   * Реплікація: Дані реплікуються в реальному часі між кількома дата-центрами. Бази даних (Cassandra, PostgreSQL) працюють у режимі кластера з реплікацією.
   * Контейнеризація та хмарна інфраструктура: Система повністю контейнеризована за допомогою Docker та оркеструється через Kubernetes. Основна інфраструктура розміщена в хмарі (AWS + Google Cloud), що дозволяє динамічно масштабувати сервіси залежно від навантаження.
3.6 Приклади програмної реалізації
Використання штучного інтелекту під час розробки
Назва інструменту та версія: модель Grok 4.3
Мета використання: Штучний інтелект використовувався для пошуку та структурування інформації про архітектуру програмної системи Discord, формування плану доповіді, створення UML-діаграм та підготовки матеріалів для презентації.
Внесок автора: Самостійно було обрано тему роботи, виконано аналіз отриманої інформації, оформлено презентацію, створено слайди та відредаговано матеріали відповідно до вимог практичного заняття.
1. Запит для базового розуміння патерну
Запит до ШІ:
Поясни простими словами, що таке патерн Observer і навіщо він потрібен. Наведи простий реальний приклад з життя.
Результат:
Отримано зрозуміле пояснення патерну з прикладами (YouTube-канал, підписки на сповіщення), яке допомогло сформувати вступну частину.
2. Запит для простої реалізації патерну
Запит до ШІ:
Зроби простий приклад патерна Observer на JavaScript. Нехай буде YouTube-канал, на який підписуються користувачі і отримують сповіщення про нове відео. Код повинен бути з коментарями.
Результат:
Отримано базову реалізацію з класами Observer, YouTubeChannel та Subscriber, яку було використано як перший приклад у презентації.
3. Запит для більш реальної реалізації
Запит до ШІ:
Напиши реальніший приклад на JavaScript з EventManager. Нехай буде інтернет-магазин: коли створюється замовлення, повинні автоматично спрацьовувати EmailService і InventoryService.
Результат:
Отримано повноцінний код з центральним EventManager, класом Store та двома сервісами. Цей приклад добре показує, як Observer використовується в реальних системах.




4 ВИСНОВКИ


Архітектура Discord є сучасним прикладом високо масштабованого та ефективного рішення для систем реального часу. Вона поєднує клієнт-серверну, мікросервісну та подієво-орієнтовану (Event-Driven) архітектури, що дозволяє платформі стабільно обслуговувати сотні мільйонів користувачів одночасно.
Основні сильні сторони архітектури:
   * Висока масштабованість завдяки мікросервісам та горизонтальному масштабуванню.
   * Низька затримка та робота в реальному часі за рахунок WebSocket, Kafka та Redis.
   * Відмовостійкість і ізоляція збоїв — вихід з ладу одного сервісу не впливає на всю систему.
   * Гнучкість та швидкість розробки — сервіси можна оновлювати незалежно один від одного.
Завдяки грамотному поєднанню технологій (API Gateway, Kubernetes, Redis, Kafka, WebRTC) Discord зміг еволюціонувати від нішевого додатка для геймерів до однієї з найбільших комунікаційних платформ у світі.
Підсумок:
Вибрана архітектура повністю відповідає вимогам сучасних високонавантажених систем і є еталоном для побудови великих real-time застосунків.
