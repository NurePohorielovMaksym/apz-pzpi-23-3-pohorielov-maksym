2 ЗАВДАННЯ

   Метою практичного заняття є ознайомитися з одним із шаблонів (патернів) проєктування програмного забезпечення, проаналізувати його структуру, призначення та практичне застосування. 






3 ОПИС ВИКОНАНОЇ РОБОТИ


3.1 Загальні відомості про шаблони (патерни) проєктування 


Шаблони (патерни) проєктування — це типові рішення поширених проблем, які виникають під час розробки програмного забезпечення. Вони не є готовим кодом, а представляють собою перевірені підходи до побудови структури програми та взаємодії між об’єктами.
Основною метою використання патернів є створення гнучкого, зрозумілого та зручного для підтримки коду. Завдяки цьому спрощується розробка великих програмних систем та покращується їх архітектура.
Патерни були систематизовані групою GoF (Gang of Four), яка поділила їх на три основні категорії:
* Породжувальні (Creational) — відповідають за створення об’єктів (Singleton, Factory Method, Builder);
* Структурні (Structural) — визначають способи побудови структури класів та об’єктів (Adapter, Facade, Decorator);
* Поведінкові (Behavioral) — описують взаємодію між об’єктами та розподіл відповідальностей (Observer, Strategy, Command).
Область застосування патернів охоплює практично всі сфери розробки програмного забезпечення: веб застосунки, мобільні додатки, ігрові рушії, корпоративні системи, серверні сервіси та інші інформаційні системи. Особливо важливими патерни є в об’єктно-орієнтованому програмуванні, де правильна організація взаємодії між класами напряму впливає на ефективність та підтримуваність програмного продукту. 
3.2 Опис обраного патерна
Назва патерна: Observer (Спостерігач)
Тип шаблона (патерна): поведінковий
Основне призначення:
        Патерн Observer використовується для організації механізму сповіщення між об’єктами. Коли стан одного об’єкта змінюється, всі залежні від нього об’єкти автоматично отримують повідомлення про ці зміни.
Передумови застосування:
        Використання патерна є доцільним у випадках, коли необхідно реалізувати зв’язок «один до багатьох» між об’єктами або забезпечити автоматичне оновлення даних у кількох компонентах системи.
Переваги:
* спрощує взаємодію між об’єктами;
* забезпечує автоматичне оновлення даних;
* зменшує залежність між компонентами системи;
* підвищує гнучкість та масштабованість програми.
Недоліки:
* при великій кількості спостерігачів може знижуватись продуктивність;
* складніше відстежувати послідовність оновлень;
* можливе виникнення зайвих повідомлень між об’єктами.
3.3 Структура шаблона (патерна)
Опис структурних частин:
* Subject (Суб’єкт) — основний об’єкт, який зберігає список спостерігачів та повідомляє їх про зміни свого стану.
* Observer (Спостерігач) — інтерфейс або базовий клас, який визначає метод оновлення для отримання повідомлень.
* ConcreteSubject — конкретна реалізація суб’єкта, у якій відбувається зміна стану та надсилання сповіщень.
* ConcreteObserver — конкретний спостерігач, який отримує повідомлення та реагує на зміни стану суб’єкта.
Опис взаємодії об’єктів
Суб’єкт зберігає список спостерігачів. Після зміни свого стану він автоматично викликає метод оновлення для всіх підписаних об’єктів. Спостерігачі отримують нові дані та виконують необхідні дії, наприклад оновлення інформації або відображення повідомлення. Це забезпечує автоматичний обмін даними між компонентами системи.


  

Рис 3.1 - Uml діаграма класів 


Діаграма показує роботу патерна Спостерігач, у якому основний об'єкт суб'єкт веде список підписників і самостійно ініціює їхнє оновлення через метод notifyObservers. Завдяки абстрактному інтерфейсу Observer, суб'єкт може взаємодіяти з будь-якими конкретними класами спостерігачів, просто викликаючи їхній метод сповіщення в циклі. Така архітектура дозволяє легко змінювати поведінку системи та додавати нові типи об'єктів, які мають реагувати на події, зберігаючи при цьому слабку пов'язаність компонентів і автоматичний обмін даними.


3.4 Реалізація шаблона (патерна)  
Реалізація шаблона Observer була виконана мовою програмування JavaScript. Для створення, перевірки та оптимізації прикладів коду було використано штучний інтелект Grok.
Основні етапи реалізації:
1. Створення базових інтерфейсів
Було створено базовий клас Observer, який визначає загальний метод update(), що буде реалізований усіма конкретними спостерігачами.


 1  // Базовий клас спостерігача (Observer)
 2  class Observer {
 3      update(data) {
 4          // Метод, який перевизначається в конкретних спостерігачах
 5      }
 6  }


2. Реалізація конкретних класів
Створено клас-видавець YouTubeChannel, який управляє списком підписників, а також клас конкретного спостерігача Subscriber.


 1  // Клас-видавець (Subject) — YouTubeChannel
 2  class YouTubeChannel {
 3      constructor() {
 4          this.subscribers = [];   // Список усіх підписників
 5      }
 6  
 7      // Додавання спостерігача
 8      subscribe(observer) {
 9          this.subscribers.push(observer);
10      }
11  
12      // Видалення спостерігача
13      unsubscribe(observer) {
14          this.subscribers = this.subscribers.filter(sub => sub !== observer);
15      }
16  
17      // Сповіщення всіх підписників
18      notify(videoTitle) {
19          this.subscribers.forEach(observer => {
20              observer.update(videoTitle);
21          });
22      }
23  }
24  
25  // Конкретний спостерігач (ConcreteObserver)
26  class Subscriber extends Observer {
27      constructor(name) {
28          super();
29          this.name = name;
30      }
31  
32      update(videoTitle) {
33          console.log(`${this.name} отримав повідомлення: Нове відео "${videoTitle}"`);
34      }
35  }


3. Демонстрація використання
Демонстрація практичного застосування патерна: створення каналу, підписка користувачів, публікація відео та відписка.


 1  // Демонстрація роботи патерна Observer
 2  const channel = new YouTubeChannel();
 3  
 4  const user1 = new Subscriber("Максим");
 5  const user2 = new Subscriber("Анна");
 6  
 7  // Підписка користувачів
 8  channel.subscribe(user1);
 9  channel.subscribe(user2);
10  
11  console.log("Канал опублікував нове відео:");
12  channel.notify("Observer Pattern в JavaScript");
13  
14  // Відписка одного користувача
15  channel.unsubscribe(user2);
16  
17  console.log("\nПісля відписки Анни:");
18  channel.notify("Нове відео про дизайн-патерни");


Результат реалізації:
Патерн Observer успішно забезпечує слабку зв’язність між об’єктами. Клас YouTubeChannel не залежить від конкретних типів підписників, що дозволяє легко додавати нових спостерігачів та розширювати систему.




4 ВИСНОВКИ


Патерн Observer є одним із найпоширеніших поведінкових шаблонів проєктування, який використовується для організації взаємодії між об’єктами за принципом «один до багатьох». Його основне призначення полягає у забезпеченні автоматичного сповіщення всіх залежних об’єктів при зміні стану основного об’єкта.
Застосування цього патерна дозволяє зменшити залежність між компонентами системи, зробити програму більш гнучкою та спростити її подальшу підтримку і масштабування. Observer особливо ефективний у системах сповіщень, чатах, веб застосунках, event-driven системах та інших програмних рішеннях, де необхідна швидка передача змін між компонентами.
Незважаючи на певні недоліки, такі як складність відстеження великої кількості сповіщень або можливе зниження продуктивності, патерн Observer залишається важливим інструментом сучасної розробки програмного забезпечення та широко використовується на практиці.

2. Напиши реалізацію реального коду патерна Observer на JavaScript у стилі інтернет-магазину з EventManager. Зроби дві частини:
1 частина:
* Клас EventManager з методами subscribe() та notify()
* Класи EmailService та InventoryService


 1  class EventManager {
 2      constructor() {
 3          this.listeners = {};   // Об'єкт для зберігання списків обробників
 4      }
 5  
 6      // Реєстрація нового спостерігача
 7      subscribe(eventType, listener) {
 8          if (!this.listeners[eventType]) {
 9              this.listeners[eventType] = [];
10          }
11          this.listeners[eventType].push(listener);
12      }
13  
14      // Сповіщення всіх підписників конкретної події
15      notify(eventType, data) {
16          if (this.listeners[eventType]) {
17              this.listeners[eventType].forEach(listener => {
18                  listener.update(data);
19              });
20          }
21      }
22  }
23  
24  // Конкретний спостерігач 1
25  class EmailService {
26      update(orderId) {
27          console.log(`EmailService: Відправлено лист з чеком для замовлення #${orderId}`);
28      }
29  }
30  
31  // Конкретний спостерігач 2
32  class InventoryService {
33      update(orderId) {
34          console.log(`InventoryService: Товар для замовлення #${orderId} зарезервовано на складі`);
35      }
36  }


2 частина:
* Клас Store з методом createOrder()
